# ATLAS v3.3 · 需求规范化 → 方案对比 → 交付排期（含市场抓取后端）

一句话：第一页把「一段自然语言需求」变成可逐条勾选的规范条目，第二页把这堆条目变成 280 个型号里的
一套 BOM 方案并排出交付甘特图，`backend/` 负责从平台抓真实商品、人工审核后写回零件库。

本文只讲三件事：**这一版有什么**、**怎么启动和用**、**数据存在哪**。
每个子目录的细节（接口、字段、算法推导）见各自的 `pages/README.md`、`backend/README.md`。

```
atlas/
  ai-config.env        ← 全项目唯一一份 AI 配置（前后端共用）
  ai-config.env.example   配置模板（不含 Key，随包分发）
  pages/               第一页 + 第二页，端口 43125，零依赖
  backend/             市场抓取 / 审核 / 检查，端口 43130，零依赖
  scripts/             生成零件库、生成 28 张零件图、打分发包
```

# 一、这一版包含什么，能做什么

## 1.1 第一页 · 需求规范化（http://127.0.0.1:43125/）

| 能力 | 具体实现 |
| --- | --- |
| 身份码 | 打开页面先填身份码（2–32 位字母 / 数字 / 下划线 / 短横线 / 中文，统一小写）；目录已存在就问「是否登录」，不存在就问「是否创建」。每个身份码对应本地一个文件夹 |
| 三个问题 | 商品类型 → 硬性约束 → 零件拆解，一屏一个问题，回答用自然语言 |
| AI 只走预设函数 | 每次请求只允许调用一个预设函数，参数走严格 JSON Schema 校验；模型不能自由发挥、不能自造零件 code |
| 逐条确认 | 每轮结果在弹窗里一条条列出，点卡片切换选中，边框高亮表示生效 |
| 三个出口 | 弹窗底部固定三个动作：拒绝全部重来 / 保留已选重来 / 保留已选继续 |
| 双输出 | 一次请求同时产出「规范化 JSON」和「人话摘要」，前者给下游，后者给用户核对 |
| 表1 校验 | 零件只能从 `presets/table1.json` 里选（1 个整机 / 7 个模块 / 28 个零件），页面右下角可看表1 全文 |
| 保存与恢复 | 三个问题都确认后命名保存（默认 `untitled1`、`untitled2`…）；右上角「我的」可列出历史产品、点一行直接恢复 |
| 会话行为 | 刷新不清进度；关标签页才清空并回到身份码入口；同一浏览器多标签页互不干扰 |
| 交接 | 点「进入下一阶段」把整份 JSON 交给第二页；交接令牌 12 小时过期，只有同一身份码能读回 |

第一页**不联网也能跑**：`ai-config.env` 留空时自动回落到本地预设函数（MOCK），输出结构完全一样，只是内容是规则模拟的。

## 1.2 第二页 · 方案对比 + 交付排期（http://127.0.0.1:43125/next.html）

只有两个页签：**01 方案对比**、**02 交付排期**（原来的「结构爆炸」占位页已删除，「周期风险」「人员协作」合并进交付排期）。

**方案对比**

| 能力 | 具体实现 |
| --- | --- |
| 零件库 | 7 个模块 / 28 个零件类型 / **280 个型号**（每个类型 10 个：基础四款「标准 / 轻量 / 增强 / 旗舰」+ 两个厂家各 3 款）；每个型号有厂家、型号、核心参数、性能分、单价、重量、交期、风险、来源 |
| 系统推荐 | 「极速引擎」= 五起点爬山（全标准件 / 全最低价 / 全最轻 / 全最高性能 / 全最低风险各爬一次，取分数最高的一路）；换掉的格子前面有青色圆点，评分区顶部写着是哪个起点赢的 |
| 用户自配 | 左侧按模块 / 零件类型展开 10 个型号，点「加入」写入当前方案；每点一次右侧新增一列，删掉中间列自动补号 |
| 对比矩阵 | 系统推荐 + 用户自配逐格对比；标题位置直接列出第一页的 4 条硬约束 + 1 条软约束，悬停看条件与达标状态 |
| 加权评分 | 成本 / 重量 / 性能 / 风险 / 约束五个维度可拖权重；**交期已并入风险**（风险等级 60% + 交期档位 40%）；硬约束不满足封顶 20 分、软约束不满足封顶 60 分 |
| 场景预设 | 均衡 / 成本优先 / 轻量优先 / 安全优先 / 性能优先，一键换权重 |
| 零件详情 | 右侧详情栏：顶部一张该零件类别的示意图（28 类各一张，同类 10 个型号共用），下面是厂家 / 型号 / 核心参数 / 性能分 / 单价 / 重量 / 交期 / 风险分 |

**交付排期**

| 能力 | 具体实现 |
| --- | --- |
| 任务拆分 | 13 项任务 = AI 3 项（到料预测 / 装配排程 / 视觉检测）+ 非 AI 10 项（7 组采购、2 道装配、1 道整机检查）；人物 3 人 + AI（周予 / 陈屿 / 苏航） |
| 输入 | 用户只填两个日期：起始日期、终止日期；条形位置由交期算出，不随日期伸缩 |
| 甘特图 | 上半屏 4 条泳道（AI / 采购·周予 / 装配·陈屿 / 检查·苏航）、月份与日期刻度、周末底纹、节点 / 预警 / 延期三级预警线 |
| 流程图 | 下半屏配套流程图：7 个采购节点先汇合成两路，再进轴系组装 → 电气总装 → 整机检查，AI 单独一条带；点甘特条闪流程节点，反之亦然 |
| 资源调平 | 采购条只画「下单那半天」（占人），供应商交期画成虚线轨道 + 到料菱形（不占人）；7 张采购单按半天一个工位排开，**同一人任务绝不允许重叠**，一天最多两单；总时长与「全部第 0 天下单」完全一致（演示数据 48 天） |
| 排期卡 | 三张卡：周期风险（预警线与日期）、人员协作（每人任务数、跨度、三项调平指标：同一人重叠 0 处 / 同日开工最多 2 项 / 同日收尾最多 1 项）、排期口径 |
| 排期基准 | 可切换「系统推荐」或某个用户方案，换方案即按新方案的交期重排 |
| 窗口不够 | 窗口比计划短时，任务被压到窗口外并标红，点「按交期自动排」一键排满 |

第二页也**不联网**：全部读本地零件库与前端的评分 / 排期算法，前端不调用 `backend/` 的任何地址。

## 1.3 后端 · 市场抓取 / 审核 / 检查（http://127.0.0.1:43130）

| 能力 | 具体实现 |
| --- | --- |
| 抓取管线 | 候选商品 → 详情页 → AI 判定与抽取 → 异常价剔除 → 同款合并 → 临时表 → 人工审核 → 写回零件库（写盘前自动备份） |
| 两种平台 | `MARKET_PLATFORM=mock`（内置模拟平台，可离线跑）/ `MARKET_PLATFORM=1688`（真实抓取；详情页可抓，商品发现靠 `seeds/1688-seeds.json` 种子链接） |
| 四个预设函数 | `judge_part_type` 判断是否属于该零件类型、`extract_listing` 抽厂家 / 型号 / 价格 / 月销 / 参数、`merge_market_part` 按厂家 + 型号合并同款、`judge_same_product` 判断与表内是否同一商品 |
| 临时表 | 每次运行的候选明细（`kept` / `outlier` / `type_rejected`，含中位价）落盘，页面可查 |
| 审核页 | 待审 + 既往记录（通过 / 驳回都留档：时间、类型、厂家 / 型号、写入价格、说明、runId）；通过时执行确定性函数写盘，**不经过模型** |
| 检查页 | 启动日志、运行记录、临时表、审核队列 |
| 安全边界 | 只监听 `127.0.0.1`；所有 `/api` 必须带 token；运行锁防并行；一个类型失败不拖垮整轮 |
| 定时 | 每天固定时间自动跑一轮（`MARKET_SCHEDULE_ENABLED`），失败重试 |

## 1.4 明确的边界

- **第一页 / 第二页的前端不引用后端地址**，两个目录互不 import，都能单独启动、单独打包。
- 两端唯一的共享物是：`pages/public/data/h3-parts.json`（零件库，后端写、第二页读）和根目录 `ai-config.env`。
- 所有 AI 输出必须走预设函数 + Schema 校验；页面不直接跟模型对话。
- L4（材料 / 工艺级）拆解暂时停用；表1 目前只有 `h3` 一种整机。

# 二、怎么启动、怎么用

## 2.1 运行条件

- Windows 10 / 11（Linux / macOS 也能跑，命令一样）。
- Node.js 18 以上，推荐 22 LTS。装完在终端确认：

```bat
node -v
```

- **零依赖**：不需要 `npm install`，没有 `node_modules`，整个目录复制走就能跑。
- 两个服务用的是不同端口，可以同时开，也可以只开一个：
  - `pages`：43125（第一页 / 第二页）
  - `backend`：43130（抓取 / 审核 / 检查）

## 2.2 启动两端

用两个终端窗口，各跑一个：

```bat
:: 窗口 1 · 第一 / 第二页
cd atlas\pages
node server.mjs

:: 窗口 2 · 后端（不用后端时可以不启动）
cd atlas\backend
node server.mjs
```

也可以直接双击 `pages\启动.cmd` 和 `backend\start.cmd`（等价于上面的命令）：

- 双击后会**等服务真的起来再自动打开浏览器**，不会出现「先弹出拒绝连接、再手动刷新」；
- `pages\启动.cmd` 打开第一页（`http://127.0.0.1:43125/`）；
- `backend\start.cmd` 打开抓取页（`/run`，手动触发一次抓取），`token` 自动带上（从 `data\token.txt` 读）；
- 服务已经在跑时再双击，只打开页面、不会重复启动（不会报「端口被占用」）。

启动成功时第一页会在终端打印生效的配置和模式，例如：

```
ATLAS Requirement Intake v3.3
  URL     http://127.0.0.1:43125
  Config  ai-config.env
  AI mode live · Kimi / Moonshot · kimi-for-coding @ api.kimi.com
  Table1  表1 · 预设商品类型表 v2.0.0
  Data    data
```

### 地址表

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 第一页 · 需求规范化 | http://127.0.0.1:43125/ | 主入口 |
| 第二页 · 方案对比 / 交付排期 | http://127.0.0.1:43125/next.html | 也可以从第一页「进入下一阶段」进 |
| 第二页 · 演示数据 | http://127.0.0.1:43125/next.html?demo=1 | 跳过第一页直接看第二页 |
| 后端 · 审核 | http://127.0.0.1:43130/review?token=TOKEN | 人工通过 / 驳回 |
| 后端 · 手动抓取 | http://127.0.0.1:43130/run?token=TOKEN | 立刻跑一轮 |
| 后端 · 检查 | http://127.0.0.1:43130/inspect?token=TOKEN | 日志 / 运行记录 / 临时表 / 审核队列 |

`TOKEN` 是 32 位十六进制，第一次启动后端时自动生成，存在 `backend/data/token.txt`；
后端启动日志里也会打印带 token 的完整地址，直接点开即可。

### 改端口

```bat
set PORT=43126 && node server.mjs                        :: pages
set MARKET_PORT=43131 && node server.mjs                 :: backend（在 backend 目录里）
```

要让局域网或公网访问，再加 `set HOST=0.0.0.0`（第一页内置了 `start-tunnel.cmd` 可开 Cloudflare 临时隧道）。

## 2.3 AI 配置：根目录一份，前后端同时生效

**配置文件只有一份**：`atlas/ai-config.env`。第一页、第二页、后端都读它，改这一处两端同时生效。

```ini
AI_API_KEY=sk-...
AI_BASE_URL=https://api.kimi.com/coding/v1
AI_MODEL=kimi-for-coding
AI_TEMPERATURE=1
```

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `AI_API_KEY` | 是（留空即 MOCK） | 明文 Key，只在服务端读取，不会下发到浏览器 |
| `AI_BASE_URL` | 是 | OpenAI 兼容的 `/v1` 根地址，不要带 `/chat/completions` |
| `AI_MODEL` | 否 | 留空按地址推断（DeepSeek → `deepseek-chat`，Kimi → `moonshot-v1-8k`，其它 → `gpt-4o-mini`） |
| `AI_TEMPERATURE` | 否 | Kimi 编程模型只接受 `1`，其它家可写 `0.2` |
| `AI_TIMEOUT_MS` | 否 | 单次请求超时，默认 90000 |
| `AI_PROVIDER_NAME` | 否 | 右上角徽标显示的名称，默认按域名推断 |
| `AI_MOCK` | 否 | 设 `1` 强制回落本地预设函数（调试用） |

**改完怎么生效**

| 端 | 生效时机 |
| --- | --- |
| 第一页 / 第二页 | 每次请求都重新读文件 —— **保存后刷新页面即生效，不用重启** |
| 后端 | 每次抓取、以及每次查 `/api/status` 都重新读 —— **保存后不用重启**，下一轮抓取就用新 Key |

**兼容旧包**：老版本把配置放在 `pages/ai-config.env` 或 `pages/.env`，这两个位置仍然会被读取，
但优先级低于根目录那份；两者同时存在时以根目录为准（启动日志里的 `Config` 行会打印实际用的是哪个文件）。

**留空 = 离线可演示**：`AI_API_KEY` 清空后两端都回落到本地预设函数，输出结构不变；
右上角徽标显示「MOCK · 本地预设函数」，后端日志显示 `AI mock`。

> `ai-config.env` 含明文 Key，不要外发、不要打进分发包；`scripts/build-package.mjs` 打包时会按文件名跳过它，
> 并生成一份脱敏的 `ai-config.env.example`。

## 2.4 第一页怎么用（5 步）

1. **填身份码**。第一次用会问「是否创建」，之后同一身份码自动识别，问「是否登录」。
2. **回答问题 1：商品类型**。例如「我要一台手持的三轴云台相机，预算两千出头」。
   提交后弹窗里列出规范条目（商品类型、形态、用途…），点卡片勾选，底部选「保留已选继续」。
3. **回答问题 2：硬性约束**。例如「重量不超过 800 g、总价 2500 以内、续航 3 小时、要有 Type-C」。
   同样逐条确认；每条会标成硬约束 / 软约束。
4. **回答问题 3：零件拆解**。系统按表1 拆到 7 个模块 28 个零件，逐条确认。
5. **命名保存** → 摘要卡点「进入下一阶段」，整份 JSON 交给第二页，页面自动跳到 `next.html`。

右上角「我的」随时可以回到历史产品；「退出登录」清空本次进度（已保存的产品不受影响）。

## 2.5 第二页怎么用（对比 → 排期）

1. **进入方式**：从第一页交接进来，或直接开 `next.html?demo=1` 看演示数据。
2. **看系统推荐**：中间第一列就是「系统推荐」（极速引擎），列头写着是哪个起点赢的，换掉的格子前面有青色圆点。
3. **自己配方案**：左侧按模块展开零件类型，点型号卡片上的「加入」写进当前方案；每点「从零开始自配」新增一列；
   28 个零件填满后「开始对比」才可用。
4. **调权重**：下方五个维度（成本 / 重量 / 性能 / 风险 / 约束）拖动滑块，推荐与各列分数实时重算；
   也可以直接点场景预设（均衡 / 成本优先 / 轻量优先 / 安全优先 / 性能优先）。
5. **看零件详情**：悬停零件名或点开右侧详情栏，看该类的示意图、厂家、型号、核心参数、性能分、单价、重量、交期。
6. **切到「02 交付排期」**：选排期基准（系统推荐或某个用户方案）→ 填起始日期、终止日期 → 甘特图与流程图自动生成；
   窗口不够就点「按交期自动排」；点条形会闪对应流程节点，点图例里的泳道可以临时隐藏某个人。

## 2.6 后端怎么用（抓取 → 审核 → 写回）

1. **拿 token**：启动后端，终端会打印 `http://127.0.0.1:43130/review?token=...`，或直接读 `backend/data/token.txt`。
2. **跑一轮**：打开 `/run?token=...` 点「开始」；也可以等每日定时任务。
   `MARKET_PLATFORM=mock` 不联网、不花钱，用来演示整条链路；改 `1688` 才是真实抓取（需要种子链接或登录 Cookie，
   见 `backend/README.md`）。
3. **看临时表**：`/inspect` 里的临时表会列出本轮候选、被剔除的异常价、被判定为类型不符的条目。
4. **审核**：`/review` 里逐条看「当前产品（表内）」与「本次抓取（待写入）」的价格和链接，点通过 / 驳回；
   通过即写回 `pages/public/data/h3-parts.json`（写盘前自动备份到 `backend/data/backups/`），第二页刷新就能看到。
5. **回到第二页**：新型号出现在对应零件类型的型号列表里。

## 2.7 常见问题

| 现象 | 处理 |
| --- | --- |
| 端口被占用 | 换端口：`set PORT=43126 && node server.mjs`（后端用 `MARKET_PORT`） |
| 页面右上角显示「MOCK · 本地预设函数」 | `ai-config.env` 里 `AI_API_KEY` 是空的，或 `AI_MOCK=1` |
| 显示「配置错误 · 检查 ai-config.env」 | `AI_BASE_URL` 写错了（少了协议、多了 `/chat/completions`），终端与页面都会说原因 |
| 后端 401 | 地址里的 token 不对，重新从 `backend/data/token.txt` 复制 |
| 第一页打不开历史产品 | 身份码输错了（大小写 / 全半角），本地目录名是统一小写后的结果 |
| 交付排期图表空着 | 没填起止日期，或填的终止日期早于起始日期 |
| 想从零再来 | 关掉标签页重新打开（清空本次进度），或换个身份码 |

# 三、各核心数据存在哪

## 3.1 配置

| 数据 | 路径 | 说明 |
| --- | --- | --- |
| **AI 配置（唯一一份）** | `ai-config.env` | 第一页、第二页、后端共用；含明文 Key，**不要外发** |
| AI 配置模板 | `ai-config.env.example` | 不含 Key，随分发包发出 |
| 后端运行配置 | `backend/market-config.env` | 端口、平台（mock / 1688）、定时、抓取参数、1688 Cookie 与重试；模板见 `market-config.env.example` |
| 1688 种子链接 | `backend/seeds/1688-seeds.json` | 零件类型 → 1~4 条 1688 商品链接，真实抓取时优先用它 |
| 访问 token | `backend/data/token.txt` | 32 位十六进制，首次启动自动生成；所有 `/api` 与三个后端页面都要它 |

## 3.3 `backend/`（抓取、审核、检查）

## 3.5 备份与恢复

```bat
:: 恢复零件库到某次写回之前
copy atlas\backend\data\backups\h3-parts-<时间>.json atlas\pages\public\data\h3-parts.json

:: 备份用户的全部需求（整个文件夹复制走即可）
xcopy atlas\pages\data D:\backup\atlas-data /E /I

:: 跑测试
cd requirement-intake-v2-checks && node --test
cd atlas\backend && node --test
```

三句话总结数据边界：**`pages/data/` 是用户资产（别删）、`pages/public/data/` 是零件库与素材（可重建）、
`backend/data/` 是运行记录（可清空，会重新生成）。**
